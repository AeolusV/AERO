## 安装与启动

当前支持 Windows 源码运行，尚无安装包。准备 Node.js 24 LTS、npm 和已登录的 Codex Desktop；获取源码时请遵守 [授权说明](../LICENSE)。在仓库根目录执行：

```powershell
npm.cmd ci
npm.cmd run runtime:electron
npm.cmd run build
npm.cmd start
```

`start` 加载已构建的界面。修改源码后需要重新构建；开发时使用 `npm.cmd run dev`，不要把 `preview` 当成桌面应用启动命令。

## 控制栏与托盘

- 点击任务灯回到对应线程，悬停查看工作区名和线程名。
- 在完整栏与迷你栏之间切换；迷你栏保留六灯与返回按钮，可拖动、吸附到屏幕边缘。
- 设置中调整控件顺序、可见性、大小栏主题、灯色、品牌配色和声音。
- 关闭悬浮栏会隐藏到系统托盘，不等于退出。托盘菜单可以显示窗口、打开语音入口或彻底退出。
- 退出 AERO 会停止它管理的唤醒监听器。不要通过关闭悬浮栏来判断监听是否停止，查看语音设置中的状态。

任务灯默认使用白 / 蓝 / 绿 / 黄 / 粉表达空闲 / 运行 / 完成 / 需要输入 / 错误。状态来自后端与本地结构化事件，不是 Desktop 内部状态的直接镜像，可能存在延迟。

## 可选：本地语音唤醒

1. 在 Codex Desktop 中显式将 Voice 快捷键绑定为 `Ctrl+Shift+V`。AERO 不会替你修改它。
2. 打开 AERO 的语音设置，通过一键配置安装运行环境和英文 Vosk 模型，或选择已有的 Python 与模型路径。首次配置需要联网。
3. 选择麦克风，将唤醒词设为 `Hey Codex`，点击「检查配置」，再打开「监听」开关并确认「监听中」。设备编号可能随机器或系统变化，不要直接沿用其他人的编号。环境检查通过不代表真人唤醒已经成功。
4. 说出 `Hey Codex`。识别成功后，监听器先释放麦克风，再发送快捷键并退出。
5. Codex Voice 结束后，点击「重新监听」。当前没有自动恢复监听的可靠会话结束信号。

### 首次配置与测试唤醒

新用户无需预装 Python。一键配置会将隔离的 Python 3.12.10、Vosk 0.3.45、sounddevice 0.5.5 和英文模型下载到 AERO 用户数据目录下的 `wake-runtime`，不会把模型放进源码仓库。设置中的 Python、英文模型字段显示实际位置。首次下载需要联网；后续唤醒识别离线运行。模型 ZIP 约 40 MB，运行环境另外下载。

模型为 **vosk-model-small-en-us-0.15**：[官方模型列表](https://alphacephei.com/vosk/models) · [下载英文模型](https://alphacephei.com/vosk/models/vosk-model-small-en-us-0.15.zip)。模型压缩包 SHA-256：`30f26242c4eb449f948e42cb302dd7a686cb29a3423a8367f99ff41780942498`。

选择麦克风并检查配置后，先关闭正式监听、结束 Codex Voice，再点击「测试唤醒」。模型加载后有 30 秒识别窗口：说出唤醒词后显示「测试通过」；超时显示「未识别」；也可点击「停止监听 / 测试」。测试只在本机运行，不发送快捷键、不打开 Voice、不保存原始音频或日常转写，也不会自动开启正式监听。

测试通过只说明本地识别成功，不证明 Codex Voice 已经打开。下一步确认 Codex 已绑定 `Ctrl+Shift+V`，再打开正式监听。语音结束后仍需手动重新监听。

### 一键配置失败时

查看配置状态和日志，确认能访问 GitHub、Python 依赖下载源及上述模型地址，然后点击「一键配置」或「检查 / 修复」重试。不要关闭 Windows 安全保护。已有环境和完整模型会复用；校验失败的模型不会直接启用。

也可以手动配置：在你自己的独立 Python 3.12 环境中安装 `vosk==0.3.45`、`sounddevice==0.5.5`，从官方地址下载模型并解压。在 AERO 中选择该环境的 `python.exe` 和解压后的 `vosk-model-small-en-us-0.15` 文件夹。模型目录内应有 `am/final.mdl`、`conf/mfcc.conf`；不要选择 ZIP 或它外层的父目录。最后重新选麦克风、检查配置、测试唤醒。

Beta 2 已验证隔离目录里的首次下载、校验、模型加载和安装重试；真人发音及 Desktop Voice 打开的完整链路仍未做本轮验收。

不需要持续唤醒时，关闭监听开关，再用控制栏语音按钮或托盘语音入口发送热键即可。隐藏到托盘不会停止已开启的监听，彻底退出 AERO 才会结束它。

手动配置环境时，Python 路径应指向已安装 `vosk` 和 `sounddevice` 的可执行文件，模型路径应指向解压后的英文 Vosk 模型文件夹，不是压缩包。检查失败时先核对这两项，再查看日志；不必反复开启监听或更改全局 Python 环境。

本地唤醒不上传音频、不调用 OpenAI API，默认不记录原始音频或日常转写。Codex Voice 是另一个功能，仍遵循它自身的连接要求和使用额度。语音按钮只是尝试发送已检查的热键，不能保证 Desktop 已成功进入语音会话。

## 常见问题

**启动提示没有构建界面**：在仓库根目录运行 `npm.cmd run build`，成功后再运行 `npm.cmd start`。

**开发界面加载失败**：确认 `npm.cmd run dev` 启动成功，且本机 `127.0.0.1:5173` 未被其他服务占用；默认配置不会偷偷改用另一端口。

**无法连接 Codex**：确认 Desktop 已安装、登录且可正常使用。协议仍属实验接口，升级后可能需要适配。不要为了排查连接问题上传登录文件。

**灯色不立即变化**：本地事件和线程元数据可能有刷新延迟。若持续与实际任务不符，请提供复现步骤及版本，不要将演示宣传图当作实时状态来源。

**推理强度与输入框不同步**：档位按默认模型能力显示；任务被 Desktop 独占时，修改可能回退为后续提交的默认配置，并不保证修改当前输入框。

**唤醒无反应**：核对快捷键、麦克风、Python 与模型路径，在语音设置中查看状态和日志。触发后监听退出是正常行为，需要手动重新启用。

## 本地数据与反馈

外观与控件偏好保存在 Electron 本地存储中；窗口位置、语音配置和日志位于 Electron 的用户数据目录。语音日志可从设置直接打开。不建议通过删除整个用户数据目录来排查问题。

在 [Issues](https://github.com/AeolusV/AERO/issues) 提供 Windows、Node 和 Codex Desktop 版本、复现步骤、预期与实际行为。日志和截图先脱敏：不要附带凭证、登录配置、私密线程内容或个人工作区路径。
